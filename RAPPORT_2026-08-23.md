## 1. Ce qu'est ce projet

Un **dépôt d'exploration**, pas une base de code : ni build, ni application, ni tests. L'objet
d'étude est **la VM Claude Code elle-même** — ce qu'elle est, ce qu'elle sait faire, ce qu'elle
refuse. Le livrable est un **relevé** (`DOSSIER_VM.md`, 308 lignes) et **trois sondes** qui le
rejouent.

Sa particularité tient en une phrase du `CLAUDE.md` : *« ce dépôt décrit l'environnement dans
lequel tu tournes peut-être »*. Le sujet et le lieu d'exécution coïncident — ce rapport en est
l'illustration : il est écrit **dans** l'objet qu'il décrit.

### Origine — et pourquoi le détour est le sujet

Le dossier est né sur la branche `claude/cc-over-anthrvm` de `DeeJayMX/PXL-Tape`, puis extrait
ici le **02/08/2026 depuis un poste local**. Ce détour n'est pas de l'organisation : c'est la
**conséquence mesurée** de deux verrous qui se referment l'un sur l'autre (§4 du dossier) —

1. créer un dépôt depuis la session prend un **403** ;
2. attacher un dépôt à une session **déjà lancée** est impossible (périmètre figé au boot).

⇒ aucune séquence ne part de rien et n'aboutit à du contenu poussé dans un dépôt neuf, **en une
seule session cloud**. Le contournement retenu — écrire sur une branche dédiée d'un dépôt déjà
attaché, dont le diff contre `main` *est* le futur dépôt — a servi ici et pour `PXL-StageBox`.
Le dépôt est donc lui-même la **preuve de la contrainte qu'il documente**.

### La ligne éditoriale, et elle est inhabituelle

Trois règles structurent tout le reste, et elles sont plus intéressantes que la plupart des
mesures qu'elles encadrent :

| Règle | Ce qu'elle implique |
|---|---|
| **Document de mémoire, pas d'état courant** | une divergence se **mesure, se date, s'ajoute** — jamais « mettre à jour ». Un chiffre daté qui a changé prouve la variabilité ; le même chiffre écrasé ne prouve plus rien |
| **Ne jamais citer un chiffre du dossier comme vérité de la session** | relancer la sonde. Corollaire direct de la précédente |
| **Les errata ne se nettoient pas** | ils consignent des raisonnements faux **avec leur mécanisme** — précisément ceux qui seront refaits |

Le dossier sépare partout **mesuré / calculé / supposé**, avec une signalétique tenue (⭐ fait
porteur · ⚠️ réserve · 🔴 bloquant), et n'admet que **trois points non mesurés**, marqués comme
tels : la localisation de la VM, la durée de recyclage côté doc officielle, la seconde des deux
couches du refus GitHub.

## 3. Le dossier, section par section

### §1 — La machine
Firecracker microVM, kernel 6.18.x x86_64, **4 cœurs / 15 Go**, horloge UTC, `df` trompeur (le
quota est le chiffre **libre**, 30 Go, pas les 252 Go affichés). Localisation **indéterminable**
de l'intérieur (metadata bloquée) — AWS *supposé*, explicitement non confirmé.

⭐ **Le fait porteur** : le **CPU change d'une session à l'autre** (Xeon @2,80 GHz les 25-27/07,
@2,10 GHz le 01/08). Conséquence qui déborde du dépôt : les fps absolus du banc SVT-JPEG-XS de
`PXL-StageBox` ne sont pas reproductibles entre sessions ; seuls les **rapports** le sont. La
méthode de la **référence réintercalée**, adoptée là-bas pour une autre raison (cache pollué),
s'en trouve justifiée *a posteriori*. C'est le plus bel enchaînement du dossier : une mesure
d'environnement qui valide rétroactivement une méthode de banc.

### §2 — Le cycle de vie
La section la mieux instruite. Recyclage **~3 min** après le dernier tour (mort bracketée) ;
`nohup` **tué en vol** ; `run_in_background` **maintient la VM en vie** (720/720 incréments sur
1 h, sans un trou) ; `send_later` ressuscite la session à la seconde ; scratchpad persistant à
travers les recyclages ; conversation persistante côté serveur.

🔴 **La correction du 01/08** est le morceau de méthode du dossier. La note du 27/07 affirmait
un re-clone à chaque VM. Mesure contradictoire : `mtime` de `/home/user` **antérieur au boot**,
`.git` à boot+5 s, **reflog non vide avec entrées antérieures au boot**. ⇒ l'opération de
boot+5 s est un **rafraîchissement**, pas un clone. Et immédiatement la réserve, qui est ce qui
distingue ce dossier d'un simple relevé : *un seul recyclage observé* ⇒ **« push = survie »
reste la règle**. **Ce qui change est le diagnostic, pas la discipline.**

### §3 — Le réseau
Egress par `HTTPS_PROXY` (port aléatoire par session), CA bundle en `/root/.ccr/`. Deux faits
⭐ : l'endpoint d'introspection `"$HTTPS_PROXY/__agentproxy/status"` (à interroger **avant** de
suspecter son propre code), et surtout — **le proxy n'est pas un tunnel mais un point
d'application de politique** : il connaît le périmètre de la session et **réécrit les réponses
de l'API GitHub** hors périmètre (`GET /zen` rend un message de politique, pas du GitHub).
C'est la clé qui explique le §4.

### §4 — GitHub : deux couches
Pas de `gh` CLI ; deux chemins aux droits différents (relais git, serveur MCP). Tableau de
verdicts mesurés : clone/fetch/pull ✅, push création ✅, push mise à jour ✅ — mais 🔴
`push --delete` **403 sur le POST `receive-pack`** (l'annonce `GET` passe : le refus est
tardif), 🔴 création de dépôt **403**, et pas d'outil MCP de suppression de ref.

La nuance à deux couches (proxy de session *vs* permissions de l'App GitHub) est exposée avec
honnêteté : le message reçu vient de GitHub, donc l'appel a probablement porté jusque-là, mais
**la conclusion opérationnelle est la même** — et définitive.

**Contournements consignés** : vider une branche par un commit plutôt que la supprimer ; écrire
le futur dépôt sur une branche dédiée d'un dépôt attaché.

### §5 — Outillage
Présent : git, make, cmake, gcc, **clang 18**, node 22, python3, rustc, go, **docker**,
Chromium + Playwright. Absent : `gh`, `ffmpeg` en PATH, cross-gcc ARM, **`qemu-user`**.

⭐ **Compiler ARM sans cross-toolchain** — `clang --target=aarch64-linux-gnu`, en-têtes issues du
*resource dir* de clang, aucun sysroot requis pour un fichier autonome ; validé sur les deux
kernels NEON de `PXL-StageBox` (`ld2`/`umaxp` lus au désassemblage). ⚠️ Et la limite énoncée
sans détour : **la correction se prouve, l'exactitude non** — sans `qemu-user`, rien d'ARM ne
s'exécute.

### §6 — Navigateur, WebGPU, WebCodecs
Chromium 141 préinstallé. WebGPU ✅ via **SwiftShader** (Vulkan logiciel), pipeline compute WGSL
complet validé avec readback ; WebCodecs **VP9/AV1** ✅, **H.264/HEVC** ❌ (build sans codecs
propriétaires) ; ~1 500 slots NV12 1080p alloués (~4,7 Go) — *la « VRAM » **est** la RAM du
conteneur*.

Cinq pièges déjà payés, dont deux 🔴 : **contexte sécurisé obligatoire** (`navigator.gpu` et
`VideoDecoder` absents sur `about:blank`/`data:`) et **Chromium hérite de `HTTPS_PROXY`** et
route `127.0.0.1` à travers ⇒ `goto` pendu, d'où `proxy: {server:'direct://'}`. Le §6 se clôt
sur une **division du travail** VM/local qui est la vraie conclusion utile du dossier : logique
pure et comportement fonctionnel dans la VM, **vérité physique** (H.264/HEVC, GPU réel, NVDEC,
4K, timings) sur machine locale.

### §7-§9 — Hors d'atteinte, errata, sources
Le §7 récapitule huit impossibilités avec renvoi à leur mesure. Le **§8 est la section la plus
précieuse** : cinq errata, chacun avec sa **leçon** dégagée du mécanisme —

1. inférence d'une opération à partir de son *timing* seul ;
2. explication d'un refus par la première cause plausible quand l'environnement en empile deux ;
3. **« la description d'un outil décrit son intention, pas la politique de l'environnement qui
   l'héberge »** (`add_repo`) — l'erreur dont ce dépôt entier est né ;
4. `executablePath` versionné pour Chromium alors qu'un lien stable existe ;
5. sous `set -o pipefail`, `curl … | grep` échoue *même quand grep trouve* (curl sort 56 sur un
   CONNECT refusé) ⇒ **capturer avant de filtrer quand la gauche a le droit d'échouer**.

## 4. Les sondes, lues de près

**`vm_survey.sh`** — lecture seule (~10 s), sauf `--canary` qui écrit `/home/user/.vm_canary`
**dans le workdir** et non dans `$HOME` (= `/root`) : c'est la survie du *workdir* qu'on teste,
et le commentaire le dit. Quatre blocs : machine, persistance du workdir, réseau (statut proxy
parsé en Python, hors-allowlist, noProxy direct, metadata, réécriture GitHub), outillage. La
leçon de l'errata 5 est **appliquée dans le code** : `out=$(curl … || true)` puis `grep` sur la
variable, avec le commentaire qui explique pourquoi.

**`webgpu_probe.mjs`** — sert une page en `http://127.0.0.1:<port>` (piège 1), lance Chromium
avec `--no-proxy-server` (piège 2) et les quatre flags SwiftShader, vérifie `isSecureContext`,
exécute un vrai pipeline compute WGSL (`x[g.x] *= 2.0` sur 8 flottants, readback mappé), teste
une texture `r8unorm` 1080p, puis interroge `VideoDecoder.isConfigSupported` sur quatre codecs.
C'est une **sonde honnête** : elle prouve le calcul, pas seulement la présence de l'API.

**`vram_probe.mjs`** — relève les limites de l'adaptateur, puis alloue des slots NV12 1080p par
paliers 100/300/600/1000/1500 en **écrivant dedans** (pour forcer le commit mémoire) sous
`pushErrorScope('out-of-memory')`. Reproduit exactement la géométrie du ring PXL (Y `r8unorm`
1920×1080 + UV `rg8unorm` 960×540, ~3,1 Mo/slot).

## 6. Défauts constatés

### 🔴 D1 — `vm_survey.sh` : le test de persistance est un **faux positif par construction**

Ligne 37 :

```bash
n=$(git -C "$d" reflog --date=unix --format='%ad' 2>/dev/null | awk -v b="$BOOT" '$1 < b' | wc -l)
```

`%ad` est la **date d'auteur du commit pointé**, pas la date de l'entrée de reflog — celle-ci
est `%gd`. Mesuré aujourd'hui sur ce dépôt, dont le workdir est manifestement neuf :

```
ad=1785673587   (02/08, date du commit)   <  boot=1787507273
gd=HEAD@{1787507279}  (23/08 17:47:59)    >  boot
```

⇒ la sonde annonce **« clone SURVIVANT (3 entrées antérieures au boot) »** sur un clone neuf.
Tout dépôt dont les commits précèdent le boot — c'est-à-dire **tous** — déclenche le faux
positif. Le verdict n'est donc jamais informatif, et il l'est d'autant moins qu'il *contredit*
le canari dans la même sortie (« aucun (première pose) »).

Correctif d'une ligne, `%ad` → `%gd` avec extraction du timestamp :

```bash
n=$(git -C "$d" reflog --date=unix --format='%gd' 2>/dev/null \
    | sed -n 's/.*@{\([0-9]*\)}.*/\1/p' | awk -v b="$BOOT" '$1 < b' | wc -l)
```

⚠️ **Portée sur le §2 du dossier** : la mesure du 01/08 ne repose pas *seulement* sur ce compte
— le `mtime` de `/home/user` **76 min antérieur au boot** est un indice indépendant et suffisant.
La conclusion du §2 tient donc. Mais la formulation *« dont des commits faits à 18:00 UTC »*
suggère que la même confusion `%ad`/`%gd` a pu s'y glisser : **l'indice à citer est le `mtime`,
pas le compte de reflog.** C'est un errata 6 candidat, et de la même famille que le 1 et le 5 —
*une valeur lue n'est pas la valeur qu'on croit lire*.

### ⚠️ D2 — Les deux `.mjs` contredisent l'errata 4 du dossier

`webgpu_probe.mjs:17` et `vram_probe.mjs:10` portent toujours
`executablePath: '/opt/pw-browsers/chromium-1194/chrome-linux/chrome'` — exactement le chemin
versionné que le §6.5 et l'errata 4 déclarent **inutile**, le lien stable
`/opt/pw-browsers/chromium` existant. La révision est encore 1194 aujourd'hui, donc les sondes
tournent — **jusqu'au jour où l'image bouge**, et le kernel prouve qu'elle bouge. La correction
est documentée mais pas appliquée au code qu'elle vise.

### ⚠️ D3 — Les deux `.mjs` ne sont pas exécutables en l'état

`playwright@1.56.1` n'est installé qu'en **global npm** (`/opt/node22/lib/node_modules`), et
**ESM n'honore pas `NODE_PATH`** : `import { chromium } from 'playwright'` échoue en
`ERR_MODULE_NOT_FOUND`, avec ou sans `NODE_PATH`. Vérifié aujourd'hui. Deux voies, toutes deux
testées :

```bash
ln -s /opt/node22/lib/node_modules node_modules   # vérifié OK
# ou : npm i playwright   (le registre npm est en noProxy, direct)
```

Le README invoque les trois sondes au même niveau alors qu'une seule se lance telle quelle.

### ⚠️ D4 — Le README a un compte d'errata périmé

README : *« quatre entrées, dont trois sont des inférences fausses »*. `CLAUDE.md` : *« trois
des cinq entrées »*. Le dossier en contient **cinq**. Le 5ᵉ (celui sur `pipefail`) a été ajouté
sans que le README suive — ironie douce pour un dépôt dont la règle est que les errata
s'ajoutent.

### ○ D5 — Points mineurs

- `vm_survey.sh` n'a pas le bit exécutable (`100644`) ; sans effet, le README l'appelle par
  `bash`, mais le shebang laisse croire l'inverse.
- Le README ne mentionne pas le prérequis Playwright des sondes `.mjs` (cf. D3).

## 7. Appréciation

**Ce que le projet fait très bien.**

1. **La discipline épistémique.** Séparer *mesuré / calculé / supposé*, marquer les trois seuls
   points non mesurés, et surtout **maintenir la règle pratique quand le diagnostic tombe**
   (§2 : « ce qui change est le diagnostic, pas la discipline ») — c'est rare et c'est juste.
2. **Les errata comme livrable.** Ils ne consignent pas des fautes mais des **mécanismes de
   raisonnement** qui se reproduiront. L'errata 3 (« la description d'un outil décrit son
   intention, pas la politique de l'environnement ») est une leçon générale, pas une note de
   VM.
3. **L'utilité opérationnelle immédiate.** Le §4 et le §7 font gagner des heures : ils disent où
   **ne pas** perdre de temps, et le disent avec la mesure derrière.
4. **Les liens transverses tenus.** §1 → méthodologie du banc `PXL-StageBox` ; §5 → limite
   « bit-exact non prouvé » ; §6 → division VM/local. Le dossier n'est pas un relevé isolé, il
   **arbitre des décisions d'ingénierie ailleurs**.

**Ce qui l'affaiblit.** Un seul point sérieux : **le code des sondes est en retard sur le
dossier** (D1, D2, D3). Un dépôt dont la thèse est *« relancer la sonde plutôt que citer un
chiffre »* a besoin que la sonde soit exacte — D1 lui fait rendre un verdict systématiquement
faux sur précisément le fait qu'il présente comme décisif.
